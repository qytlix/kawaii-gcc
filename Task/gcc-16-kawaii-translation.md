# GCC 16 — 可爱化翻译补全计划

## 背景

GCC 9 → GCC 16 迁移完成。现有 514 条精确匹配的可爱化翻译已保留。剩余 ~14,000 条非可爱化条目需要处理。

## 数据现状

```
src/
├── zh-origin.po              # GCC 16.1.0 官方翻译 (101,045 行)
├── zh_CN-kawaii.po           # 当前完整 .po (514 条可爱化 + GCC 16 官方翻译)
└── zh_CN-kawaii-patch.po     # 仅可爱化修改条目
```

| 类别 | 数量 | 说明 |
|------|:----:|------|
| 已可爱化（精确匹配） | 514 | 完美保留，已在 `.po` 中 |
| 未可爱化条目 | ~14,000 | GCC 16 官方翻译（需决定哪些可爱化） |
| 其中：用户可见的诊断/错误/警告 | ~10,000 | **可爱化目标** |
| 其中：技术性/选项说明/内部日志 | ~4,000 | **保留官方翻译** |

## 策略

### 范围划分

**可爱化（~10,000 条）** — 用户编译代码时可能看到的：

- 所有 `error:` / `warning:` / `note:` 类消息
- `-W*` 选项控制的诊断消息（c-family、cp/、fortran/ 等前端）
- GCC driver 输出（`gcc.cc` 中的用户可见消息）
- 代码生成/优化决策的用户可见消息（`cif-code.def` 等）
- 所有格式参数消息（含 `%<`、`%q`、`%s`、`%d` 等）

**保留官方翻译（~4,000 条）** — 用户通常不会直接看到的：

| 类别 | 来源路径关键字 |
|------|---------------|
| LTO 内部选项/日志 | `lto/` |
| dump/调试输出 | `dumpfile`, `dbgcnt` |
| 选项 --help 描述 | 所有 `.opt` 文件中的 `--help` 类描述文本 |
| 内部优化决策日志 | `ipa-inline`, `ipa-fnsummary`, `ipa-cp`, `ipa-sra` |
| RTL/后端内部 | `lra`, `reload`, `ira`, `sched`, `cfg` |
| 代码生成工具 | `genmatch`, `genoutput`, `genpreds`, `genemit` |
| 调试/ASAN/UBSAN/TSAN 内部 | `asan`, `ubsan`, `tsan`, `sancov` |
| Dwarf/调试信息 | `dwarf*`, `dbx*` |
| 内部检查器 | `auto-profile`, `coverage`, `profile` |

### 分批方案

分 **4 批** 处理，每批 ~2,500 条：

| 批次 | 内容 | 文件 |
|:----:|------|------|
| **1** | c-family 诊断（C/C++ 前端错误/警告） | `c-family/`, `cp/` 来源的消息 |
| **2** | Fortran / D / Ada / Go / Rust / ObjC 前端诊断 | `fortran/`, `d/`, `ada/`, `go/`, `rust/`, `objc*`, `objcp*`, `m2/` |
| **3** | GCC driver / 通用诊断 / 选项冲突 | `gcc.cc`, `opts-*`, `config/*` 用户可见消息 |
| **4** | 代码生成 / 优化 / cif-code / 其他杂项 | `cif-code.def`, `tree-*` `gimple-*` 中非技术性消息 |

### LLM 翻译要求

为每批生成可爱化翻译时，**风格参考** 现有的 514 条已可爱化条目，特征：

- **语气**：轻松、俏皮，非正式
- **常用词**：
  - `喵~` — 句尾语气词
  - `啦` / `哦` / `呢` / `吧` — 句尾
  - `笨蛋` — 轻度责备
  - `拜托` / `哎哟` — 感叹
  - `还不快~` / `可别~` — 劝告语气
  - `好嘛` — 妥协
  - `是不是` / `~呢~` — 反问
  - `长点心吧` — 吐槽

### 翻译规则

1. **格式参数必须保留**：`%s`、`%d`、`%<` `%>`、`%q`、`%'` 等格式符必须原样保留在 msgstr 中
2. **不改变消息含义**：只是语气可爱化，不是改功能描述
3. **一行一条规则**：msgid 跨行时，msgstr 也必须对应跨行
4. **不破坏中文翻译质量**：保留专业术语的准确翻译（如 "内联"、"寄存器"、"优化等级"）

## 参考文件

`Task/zh_CN-kawaii-fuzzy-ref.po` — 32 条错误匹配的可爱化 fuzzy 条目（来自旧 GCC 9 的翻译），其中部分可修正后复用。

## 验证

每批完成后：
1. `make clean && make` — 确保编译通过
2. 检查 `.mo` 文件消息数
3. (可选) `msgfmt -c -o /dev/null src/zh_CN-kawaii.po 2>&1 | grep -v "format specifications"` 检查是否为同一类已知问题
