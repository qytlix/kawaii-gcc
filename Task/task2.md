# Task 2: GCC 13 迁移到 GCC 15 计划

## 项目概述

kawaii-gcc 项目通过修改 GCC 编译器的本地化文件（.po 文件），将编译器的错误信息和警告信息转换为可爱风格。当前项目基于 **GCC 13.1** 版本，需要迁移到 **GCC 15** 版本。

## 迁移目标

| 目标项 | 当前状态 | 目标状态 |
|--------|----------|----------|
| GCC 版本 | 13.1-b20230409 | 15.x |
| 本地化文件 | gcc 13 版本 .po | gcc 15 版本 .po |
| 兼容性 | GCC 13 | GCC 15 |

## 迁移步骤

### 步骤 1: 获取 GCC 15 原始本地化文件

**任务**: 从 GCC 官方仓库获取 GCC 15 的原始本地化文件

**执行方式**:
1. 访问 GCC 官方 SVN 仓库: `svn://gcc.gnu.org/svn/gcc/trunk/libstdc++-v3/po/`
2. 或者从 GCC 15 源代码包中提取本地化文件
3. 获取以下语言的原始 .po 文件：
   - `zh_CN` - 简体中文
   - `zh_TW` - 繁体中文
   - `ja` - 日语

**输出文件**:
- `src/zh-origin-15.po` - GCC 15 原始简体中文
- `src/ja-origin-15.po` - GCC 15 原始日语（如存在）

### 步骤 2: 分析版本差异

**任务**: 对比 GCC 13 和 GCC 15 本地化文件的差异

**执行方式**:
1. 使用 `msgcmp` 工具对比两个版本的 .po 文件
2. 识别新增的消息（msgid）
3. 识别删除的消息
4. 识别修改的消息

**命令示例**:
```bash
msgcmp src/zh-origin.po src/zh-origin-15.po > diff.txt
```

**输出**: 差异报告文档，包含新增/删除/修改的消息列表

### 步骤 3: 迁移可爱化补丁

**任务**: 将现有的可爱化翻译迁移到新的 GCC 15 本地化文件

**执行方式**:

#### 3.1 处理已存在的消息
- 对于在 GCC 15 中仍然存在的 msgid，保留现有的可爱化翻译
- 使用 `msgmerge` 工具合并补丁

```bash
msgmerge -o src/zh_CN-kawaii-patch-15.po src/zh_CN-kawaii-patch.po src/zh-origin-15.po
```

#### 3.2 处理新增的消息
- 识别 GCC 15 新增的 msgid
- 为这些新消息添加可爱化翻译

#### 3.3 处理删除的消息
- 移除 GCC 15 中已删除的消息对应的补丁条目

### 步骤 4: 更新项目配置

**任务**: 更新项目文件以支持 GCC 15

**需要修改的文件**:

| 文件 | 修改内容 |
|------|----------|
| `src/zh_CN-kawaii-patch.po` | 更新 Project-Id-Version 为 GCC 15 |
| `src/ja-kawaii.po` | 更新版本信息 |
| `src/zh_TW-kawaii.po` | 更新版本信息 |
| `README.md` | 更新版本说明 |
| `README-zh.md` | 更新版本说明 |

### 步骤 5: 构建测试

**任务**: 构建并测试迁移后的本地化文件

**执行方式**:
1. 运行 `make` 命令构建 .mo 文件
2. 安装到测试环境
3. 使用测试文件验证效果

```bash
make clean
make
# 测试
cd test
./test.sh
```

**验证标准**:
- 所有可爱化消息正确显示
- 没有遗漏或错误的翻译
- GCC 15 的新消息也有对应的可爱化翻译

### 步骤 6: 更新 CI/CD 流程

**任务**: 更新 GitHub Actions 配置以支持 GCC 15

**需要修改的文件**:
